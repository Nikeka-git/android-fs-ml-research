## Текущее состояние

В реестре два модуля: **`binder-diagnostics`** — текущий диагностический Android-проект, и **[`android-poc-research`](modules/android-poc-research/)** — импортированный исследовательский снимок с исходниками, версиями PoC и существующими отчётами. Материалы второго модуля добавлены 23 октября 2026 года; сборка и запуск при импорте не выполнялись. [Сводный отчёт](docs/research/android-poc-research.md), [происхождение и хеши](evidence/imports/android-poc-research/manifest.json) доступны отдельно.

Статическая инвентаризация локального проекта `NativeBinderDiagnostics`, из которого подготовлен модуль `binder-diagnostics`, выявила следующую базовую реализацию:

| Часть | Наблюдаемое состояние |
|---|---|
| Android-приложение Kotlin/JNI/C++17 | Локальная симуляция и диагностика протокола Binder |
| Поиск кандидатов | Детерминированный поиск в локальной симуляции |
| Вспомогательные файловые API Phase 2 | Отдельные заголовки; в CMake предусмотрена проверка их компиляции, подключения к JNI/UI не найдено |
| ML, датасет, обучение и оценка модели | При инвентаризации не найдены |
| Поддержка различных файловых систем в рамках темы | Не подтверждена |

Корень Gradle-проекта находится непосредственно в [modules/binder-diagnostics/](modules/binder-diagnostics/). Незавершённые, не подключённые к активной сборке legacy-файлы `app/src/main/cpp/phase3/` исключены из этой поставки. Оригинальная локальная папка остаётся без изменений. Имеющийся диагностический прототип требует дальнейшего сопоставления с заявленной темой диплома; функциональный эксплойт и ML-модуль не подтверждены.

В исходной папке не найден `.git`, поэтому прежнюю историю коммитов и авторство отдельных изменений по ней установить нельзя. Сохранённые JUnit XML и lint-отчёт перенесены отдельно в [evidence/stored/](evidence/stored/) вместе с [манифестом происхождения](evidence/stored/manifest.json). Они прочитаны как существующие файлы; сборка и тесты при этой инвентаризации не запускались повторно. Подробности и ограничения приведены в [docs/evidence.md](docs/evidence.md).

Требования к разделам отчёта не предоставлены. Подготавливаемый предварительный отчёт нельзя считать полным отчётом для сдачи до сверки с этими требованиями.

Документы в этом каркасе описывают организацию работы. Задачи из `planning/issues.json` имеют статус «Запланировано» и не назначены участникам. Их наличие не подтверждает выполненные исследования или прошлую активность.

## Структура монорепозитория

```text
modules/
  catalog.json            # Реестр реально добавленных модулей
  binder-diagnostics/     # Текущий диагностический Android-проект
  android-poc-research/    # Единый снимок исходников и отчётов PoC
  _template/              # Шаблон описания будущего модуля
shared/                   # Место для действительно общих компонентов
experiments/              # Протоколы и подтверждения с указанием module_id
docs/                     # Общие правила, сведения о команде и сдаче
planning/issues.json      # Единый бэклог
evidence/stored/           # Сохранённые отчёты с указанием происхождения
```

Новый исследовательский или exploit-модуль можно добавить в отдельную папку `modules/<module-id>/` с описанием назначения, состояния, окружения и собственных подтверждений. Скопированный шаблон сам по себе не считается реализованным модулем. Результат одного модуля не переносится на другие без отдельной проверки. Правила структуры описаны в [docs/architecture.md](docs/architecture.md).

Для нового модуля скопируйте `modules/_template/` в папку с новым идентификатором, заполните `module.json` и README, затем добавьте запись в `modules/catalog.json`. Укажите фактическое состояние и доступные подтверждения. Создайте задачу с этим `module_id` на общей доске; добавление реализации и её проверка выполняются отдельно.

## Первое заполнение

Обновите `project.json` и `docs/team.md` подтверждёнными данными. Проверьте базовый модуль в `modules/binder-diagnostics/`, сохранённые отчёты и сведения об их происхождении. После реального повторного запуска сохраняйте новые результаты отдельно от перенесённых старых файлов и указывайте `module_id`. Проверенные способы запуска и ограничения описывайте в README соответствующего модуля.

Репозиторий и общая доска созданы; на доске используется представление Board с колонками `Todo`, `In Progress`, `Done`. Автодобавление открытых issues этого репозитория включено. Указывайте в задачах область `shared` или `module_id` и сохраняйте фактический статус работы. Общий план и ссылки на опубликованные задачи находятся в `planning/`.

Репозиторий закрытый. Доступ руководителя, комиссии и остальных участников пока не проверен: их учётные записи ещё не предоставлены. Перед сдачей нужно выдать необходимые права и проверить открытие всех ссылок.

Секреты, закрытые отчёты и большие исследовательские данные исключены правилами `.gitignore`. Ссылки на такие материалы можно вести в реестре с указанием необходимого доступа.

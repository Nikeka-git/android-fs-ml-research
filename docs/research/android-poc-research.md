# 📊 Сводный отчет по исследованию применимости публичных эксплойтов

Этот документ содержит результаты исследования применимости ряда публичных уязвимостей и эксплойтов (CVE) для устройства **Samsung Galaxy A51 (SM-A515F, Exynos 9611, Linux 4.14.113, Android 11, патч март 2021)**. 

Исходный код некоторых PoC не сохранился, однако в отчете зафиксированы результаты проверки среды, логи ошибок и причины, по которым данные векторы атак оказались неработоспособными. Эти данные критически важны, для возможности отсеивать неподходящие эксплойты на основе характеристик устройства.

---

## 1. CVE-2022-22706: ARM Mali GPU Page-Cache Write

### 📝 Описание уязвимости
Уязвимость в драйвере GPU ARM Mali. Позволяет непривилегированному процессу получить доступ на запись к страницам памяти (page-cache), которые должны быть доступны только для чтения (например, к системным файлам). Это достигается за счет ошибки в проверке флагов (`KBASE_REG_GPU_WR` vs `KBASE_REG_CPU_WR`) при вызове `ioctl(MEM_IMPORT)`.

### 🎯 Проверка на устройстве
*   **Наличие драйвера:** Устройство имеет уязвимый драйвер `/dev/mali0` (версия r11p27, что подтверждено вызовом `ioctl(0)`).
*   **Результат:** **ПРОВАЛ (SELinux / EPERM).**
*   **Детали:** При попытке вызвать `ioctl` с командой `MEM_IMPORT` (или другими командами управления памятью GPU) из контекста приложения (`untrusted_app`) или `shell`, SELinux возвращает `Operation not permitted` (EPERM). Политика безопасности Samsung жестко блокирует прямой доступ к памяти GPU для не-системных процессов.

### 🐛 Ошибки при тестировании
*   `ioctl(52)` (VERSION_CHECK) возвращал `EPERM`, в то время как `ioctl(0)` работал. Это указывает на избирательную блокировку команд на уровне SELinux.
*   Попытка обойти ограничение через `run-as` (контекст `runas_app`) также не удалась — `exec` из `/data/local/tmp` был заблокирован.

### 🤖 Критерии
*   **Отсеивать, если:** `selinux_enforcing` = 1 и `mali_ioctl_access` = denied.
*   **Выбирать, если:** Устройство имеет root или SELinux в режиме Permissive.

## 2. CVE-2021-25458: Samsung ION Driver UAF

### 📝 Описание уязвимости
Double Free в драйвере ION (управление памятью Android) на устройствах Samsung. Уязвимость возникает при вызове `ion_iovmm_map` с некорректно сформированным буфером (из rbin-хипа). Приводит к повреждению памяти ядра и потенциальному повышению привилегий.

### 🎯 Проверка на устройстве
*   **Наличие драйверов:** Устройство имеет `/dev/ion` (доступен), но драйверы-триггеры (`/dev/g2d`, `/dev/fimg2d`, `/dev/m2m1shot_scaler0`) заблокированы для чтения/записи из userspace.
*   **Результат:** **ПРОВАЛ (SELinux).**
*   **Детали:** Для вызова `ion_iovmm_map` требуется передать буфер через драйвер (например, G2D). Проверка через `dd if=/dev/g2d` и `/dev/m2m1shot_scaler0` вернула `Permission denied`. Доступ к `/dev/ion` есть, но без триггера уязвимость не активировать.

### 🐛 Ошибки при тестировании
*   Утилита `run-as` не смогла открыть `/dev/g2d`, что подтвердило блокировку на уровне домена `untrusted_app`.
*   Устройство имеет `crw-rw-rw-` на `/dev/fimg2d`, но фактический `open()` возвращает `EACCES` (SELinux блокирует `ioctl`).

### 🤖 Критерии
*   **Отсеивать, если:** `selinux_enforcing` = 1 и нет доступа к медиа-драйверам (`/dev/g2d`, `/dev/fimg2d`).
*   **Выбирать, если:** Драйверы-триггеры доступны для записи.

## 3. CVE-2021-22555: Netfilter Out-of-Bounds Write

### 📝 Описание уязвимости
Уязвимость переполнения кучи (Out-of-Bounds Write) в подсистеме Netfilter (iptables). Позволяет перезаписать соседние объекты в памяти ядра и получить контроль над выполнением кода (LPE). Требует наличия прав `CAP_NET_ADMIN` для манипуляций с `setsockopt`.

### 🎯 Проверка на устройстве
*   **Проверка iptables:** Вызов `iptables -L` вернул `Permission denied (you must be root)`. Это означает, что базовая утилита не имеет прав.
*   **Проверка User Namespaces:** Для получения `CAP_NET_ADMIN` без root требуется создать user namespace (`unshare(CLONE_NEWUSER)`). Тестовый вызов вернул `EINVAL`.
*   **Результат:** **ПРОВАЛ (Отсутствие User Namespaces).**
*   **Детали:** В ядре 4.14 на устройстве отключена опция `CONFIG_USER_NS` (`# CONFIG_USER_NS is not set`). Без этого невозможна изоляция сетевого стека и получение необходимых capabilities.

### 🐛 Ошибки при тестировании
*   Команда `unshare(CLONE_NEWUSER | CLONE_NEWNET)` вернула `errno=22 (Invalid argument)`, что прямо указывает на отсутствие поддержки в ядре.
*   Утилита `ip6tables` также вернула `Permission denied`.

### 🤖 Критерии
*   **Отсеивать, если:** `config_USER_NS` = n (отключен).
*   **Выбирать, если:** `unshare(CLONE_NEWUSER)` возвращает 0 (успех).

## 4. Цепочка Samsung (CVE-2021-25337, CVE-2021-25369, CVE-2021-25370)

### 📝 Описание уязвимостей
Публичная цепочка эксплойтов от Google Project Zero, нацеленная на устройства Samsung с процессорами Exynos и ядром 4.14.113. Включает в себя:
*   **CVE-2021-25337 (Userland):** Эксплуатация провайдера буфера обмена Samsung.
*   **CVE-2021-25369 (KASLR Bypass):** Утечка адресов ядра через `sec_log`.
*   **CVE-2021-25370 (Kernel R/W):** UAF в драйвере Display Processing Unit (DPU).

### 🎯 Проверка на устройстве
*   **Версия ядра:** Идеально совпадает (4.14.113).
*   **Статус патча:** Устройство имеет патч безопасности за **март 2021**.
*   **Результат:** **ПРОВАЛ (Пропатчено).**
*   **Детали:** Уязвимости были исправлены в обновлении безопасности Samsung за март 2021 (SMR-Mar-2021). Так как устройство имеет именно этот патч-левел, цепочка с высокой вероятностью не сработает. Публичного PoC для неё не существует (только разбор от Project Zero).

### 🐛 Ошибки при тестировании
*   Проверка наличия драйвера DPU не дала явных признаков уязвимости (файлы существуют, но патч закрывает логику).
*   Провайдер буфера обмена возвращает ошибки доступа для непривилегированных приложений.

### 🤖 Критерии
*   **Отсеивать, если:** `security_patch_level` >= `2021-03`.
*   **Выбирать, если:** `security_patch_level` < `2021-03` и устройство Samsung Exynos.

## 💎 Итоговый вывод

Исследование показало, что для Samsung A51 (Android 11, патч март 2021) большинство публичных эксплойтов блокируются на этапе:
1.  **SELinux** (запрет доступа к драйверам и `kill` системных процессов).
2.  **Конфигурации ядра** (отсутствие `USERFAULTFD` и `USER_NS`).
3.  **Архитектурных различий** (Bad Spin требует qspinlock из 5.4+).

Единственным эксплойтом, который привел к подтвержденному результату (Kernel Panic), стал **CVE-2021-0920 (unix_gc)**. Это делает его приоритетным кандидатом при выборе вектора атаки на устройствах с ядром 4.14.
